MIAgent v3.3 design overview

MIAgent helps Codex run medical-imaging challenges with human steering.

The design keeps the agent focused on one serious solution direction at a time, while leaving enough trace for humans to verify data, baselines, jobs, results, and next experiments.

Four ideas to remember

1
The folder is the durable owner One active Codex session at a time operates the challenge record and one solution direction.
2
Humans steer at gates Without :/auto, Codex stops after candidate selection and after the implementation plan.
3
State guides; dashboard executes The current focus stays in state.md; jobs, results, readiness, and resources stay in dashboard.md.
4
Human taste is reusable Full steering stays beside the decision; trajectory.md links consequential decisions across stages.

The challenge loop

README stays high-level. The detailed router lives in skills/orchestration/challenge_run_workflow.md.

01 Understand task Record rules, data, metric, split, evaluator, and missing human-only facts.
02 Find baselines Use literature search, local skills, code/checkpoint checks, and external critic.
03 Choose direction Human selects one candidate, or :/auto lets Codex choose when safe.
04 Plan implementation Write the concrete pipeline, GPU profile plan, and Exploration Map in baseline.md.
05 Run experiments Each planned run has an immutable experiment.md Intent; profile the representative path before expensive training.
06 Analyze results Append the viewer-backed Outcome, update the Exploration Map, and keep state.md focused.

Human gates

The command system is intentionally small. Natural language is always allowed.

?

Default interactive mode

Codex asks questions when task facts, data access, evaluator validity, rules, or compute approval are unclear. It stops after baseline candidates and again after the implementation plan.

A

:/auto mode

Codex can continue end-to-end, but it still must stop for human-only access, ambiguous rules, untrusted evaluators, expensive compute approval, or safety blockers.

What each file does

Each file has a clear owner. This prevents the agent from scattering state across many logs.

challenge.md

Stable facts: objective, data paths, split, metric, evaluator, rules, submission, and open questions.

dashboard.md

Shared execution: readiness, current best, target/stop condition, resources, and active, completed, and planned jobs.

state.md

Short attention reset: current focus, needed evidence, protected coverage, active steering, and at most three likely next focuses.

trajectory.md

Append-only index of consequential agent decisions and linked human steering across focus and baseline shifts.

candidates.md

Post-critic baseline choices with evidence, runnable status, risk, and human selection.

literature.md

Challenge decomposition, problem-wise search evidence, and recomposition into a unified direction.

baseline.md

The active solution direction: implementation plan, living Exploration Map, GPU evidence, visualization, and acceptance.

experiment.md

One scientific experiment: immutable pre-run Intent, then a viewer-backed Outcome and decision after a valid result.

result_viewer.html

Required initial evidence for every prediction-producing experiment, expanded for key experiments.

Human Steering sections

Decisionful guidance stays in its owning file; trajectory.md links consequential guidance and state.md links what remains active.

How run mode works

Codex should not wait for one GPU job if approved independent work remains.

1. Read queue

Use this baseline's Planned Jobs block in dashboard.md. Every row points to an experiment.md Intent.

2. Submit in parallel

Submit independent jobs up to the resource budget. Keep Active Jobs current from scheduler evidence.

3. Diagnose terminal jobs

Failed jobs get repaired. Valid results append an Outcome; consequential decisions enter trajectory.md.

If no explicit score target is given, the default is to keep improving until the human stops. A plateau triggers targeted re-search and may change direction; a hard resource limit leaves the run blocked.
